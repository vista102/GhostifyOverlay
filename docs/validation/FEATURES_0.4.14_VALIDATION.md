# 0.4.14 곡 정보 UI·행간·채터링 검증

2026-10-27. ADOFAI 3.4.0 alpha build 26044349, UMM 0.32.5 기준입니다.

## 동작과 충돌 처리

- Ghostify 곡명·작곡가가 실제로 표시되면 기본 `scrUIController.txtLevelName`을 숨깁니다. 항목·그룹·전체 오버레이를 끄거나 모드를 비활성화하면 직접 숨기기 전 상태로 복원합니다. 곡 정보가 비어 있으면 기본 UI를 유지합니다.
- 복원 시 ADOFAI Tweaks의 활성 UI 숨김 설정만 읽습니다. 플레이/녹화 프로필의 `HideTitle` 또는 `HideEverything`이 켜져 있으면 다시 켜지 않습니다. 알려지지 않은 활성 Tweaks API에서도 숨김 상태를 보존합니다. 다른 HUD 설정을 수정하지 않습니다.
- 기본 UI는 컨트롤러 필드로 찾고, 대상·가시성이 달라질 때만 상태를 씁니다. 매 프레임 오브젝트 검색·리플렉션·반복 활성화는 하지 않습니다.
- 오버레이 탭 행간은 -20~60, 기본 0입니다. Ghostify 소유 텍스트만 변경하며 동일한 값을 반복 적용하지 않습니다. 곡명 줄바꿈 높이는 다시 측정하고 텍스트 오버플로를 허용합니다.
- 키뷰어 탭 채터링 섹션에는 ON/OFF와 0~500ms 정수 간격만 있습니다. 기본값은 OFF / 100ms입니다. 예외 키 설정과 별도 입력 탭은 없습니다.
- 플레이 중 같은 키의 마지막 허용 입력 이후 간격이 설정값 이하면 차단합니다. 차단된 입력은 기준 시간을 늦추지 않습니다. 0ms, 릴리스, Escape, 메뉴, 일시정지, 포커스 이탈은 보존합니다. 새 시도·장면 전환·모드 종료 시 상태를 초기화합니다.
- 비동기는 기존 SkyHook 콜백, 일반 입력은 현재 SDK의 `GetMainPressKeys(List<AnyKeyCode>)`에 연결합니다. 같은 프레임의 재조회는 동일한 판정을 공유합니다. 원래 게임의 키 제한·컨트롤러·터치·누적 처리 코드를 대체하지 않습니다.
- 고스트 레인은 차단 전 원시 입력을 계속 관찰합니다. 별도 KeyboardChatterBlocker가 활성화돼 있으면 내장 차단은 대기하며 외부 설정을 수정하지 않습니다.

## 출처

[ADOFAI Tweaks의 곡 정보 숨김 대상](https://github.com/PizzaLovers007/AdofaiTweaks/blob/f1d0a1e2500004f8a92c73705af8b7dc6aca2839/AdofaiTweaks/Tweaks/HideUiElements/HideUiElementsSettings.cs)을 참고했습니다. MIT 원문을 소스와 배포물에 포함합니다.

[얼불춤용 KeyboardChatterBlocker](https://github.com/fangshenghan/KeyboardChatterBlocker/tree/160270ee1b29fb40a36688eee77d3b6ef46a8812)에는 명시된 재배포 라이선스가 없어 코드·DLL을 복사하지 않고 같은 키 입력 간격 기능을 자체 구현했습니다. 키 제한이나 예외 키 설정은 추가하지 않았습니다. 검토용 원본 소스는 로컬에만 보관합니다.

설치된 KeyboardChatterBlocker 0.1.3의 관리형 메타데이터에서 호출자 버퍼 API 참조를 확인했습니다. REA Evidence `ev_810144b0dcbca32d28477ae79dc1bcaf62fbe3d2bb4fe2b00e145a71e5df6c75`, DLL SHA256 `9ccadc07f65d1e62c066a2501a5caaffc14305fdde6a7509edd537f07942f57d`. 정적 메타데이터 확인은 동시 플레이의 실측 결과를 뜻하지 않습니다.
